FORMGUARD

Auto-Save & Recovery System

Project overview

Development of an Auto-Saving Web Form for Preventing Data Loss During Long Online Applications

This project examines how long application forms can cause users to lose progress after refreshes or interruptions. FORMGUARD demonstrates how automatic drafting and identity-aware recovery can protect partially completed work and reduce re-entry burden.

About this project

Problem, solution, and purpose

The problem

Long online applications often require a user to complete many fields. If the browser refreshes unexpectedly, the tab closes, or the session ends, information can be lost. The user may need to re-enter multiple fields before continuing.

The proposed solution

Automatic saving stores a JSON draft in this browser. To continue on another device, export the draft as a .json file, move it to that device, and import it there.

Project aim

The project develops and evaluates an auto-saving web form designed to reduce data loss and improve the completion experience for long online applications.

Project objectives

  1. Develop a conventional form for comparison.
  2. Implement automatic saving of partially completed data.
  3. Restore saved data after supported interruptions.
  4. Simulate interruptions under controlled conditions.
  5. Evaluate both systems using recovery rate, lost fields, and completion time.

Technologies used

The implementation uses HTML, CSS, and JavaScript. Drafts are saved as JSON in browser storage, with JSON file export and import for manually transferring a draft to another device.

How the system works

  1. The user opens the form.
  2. The user enters a username and form data.
  3. The auto-saving mode listens for changes.
  4. The application saves the current state as JSON in this browser.
  5. On this device, a previously saved draft is restored automatically after reload.
  6. To move a draft to another device, export its JSON file and import that file on the other device.
  7. The imported draft requires full-name verification before its saved values are restored.

Limitations

Browser drafts do not sync automatically across devices. Exported JSON files must be transferred and imported manually, and contain personal information; store and share them carefully. Browser storage capacity varies by browser.

Testing and evaluation

Recovery rate, lost fields, completion time

Recovery Rate (%) = (Correctly Recovered Eligible Fields / Total Eligible Fields Entered Before Interruption) × 100

Lost Fields = Eligible Fields Entered Before Interruption − Correctly Recovered Eligible Fields

Completion Time = Time from a form attempt start until successful completion, including any time spent re-entering data.

Time Reduction (%) = ((Conventional Mean Time − Auto-Saving Mean Time) / Conventional Mean Time) × 100

How it works

Project walkthrough

  1. Open the conventional form and enter sample details.
  2. Simulate an interruption and observe that the form does not save automatically.
  3. Open the auto-saving form and enter comparable details.
  4. Check that the saved draft status updates after input changes.
  5. Use the draft recovery prompt to verify the name and restore the saved form.
  6. Compare the effect on recovery, lost fields, and completion time.
  7. Reset data between trials to prevent previous test values from affecting later runs.
